# Cross-Border D&B v1.0 实验协议（跑前写死，Review 核定后生效）

日期：2026-11-10（含 Review 有条件放行三处修订）。v0.1 已解冻；release/v0.1 不覆盖，新结果进 v1.0。

## 0. 回归门槛（先于一切）
- seed 0–2 用 v0.1 配置重跑 T1–T3，逐项复现冻结数字（|Δ|≤1e-9，pi_dense 已由 Coding 验 0 差）。不过关不扩规模。
- 实验 F 加逐 seed 输出参数；逐 seed 表为 v1.0 附录基线。

## 1. 主指标（两维，帕累托，不选赢家）
- 买家暴露 E = fraud_share：被攻击的成交笔数 / 总成交笔数（与代码 metrics.py 及 v0.1 回归基准一致，越低越好）；副列报按 billed token 加权的 E_tok。
- 卖家意图 Q = 策略卖家学到的攻击概率，最后 1/4 轮中**卖家在场（未停牌）轮次**的均值；停牌轮数与停牌期 q 单独报，不进 Q；按攻击模式分列 q_swap、q_theft，主列取 token 加权平均（越低越好）。
- active_attack_rate 与 fraud_share 同公式：删除 active_attack_rate 列，不再作为独立主指标。
- 主图：每个策略一点 (E, Q) + 95% 区间十字，标出帕累托前沿；正文不出「X 赢」的句子。J、成本、质量、合规进附录/副表。
- Q 晋升主列前提：在 ≥2 种卖家学习规则下（现有规则 + 至少一种：EXP3 或 fictitious play）策略间 Q 的排序一致（Kendall τ≥0.6 且前沿成员不变）。不满足则 Q 降为副列，仅报 E。

## 2. 规模
- 卖家 ≥40（诚实 ≥30），策略卖家 ≥3，攻击类型 ≥3：swap、theft、新增 1 种（选择性降级：仅在难题上换模型）。
- seed ≥20（主表），π 网格 {0,0.02,…,0.30, 0.5, 1.0}，n_rounds=48 不变。
- 统计：同 seed 配对差，10k 次 bootstrap，95% 区间；多重比较按策略对做 Holm 校正。

## 3. 基线
- 忠实复现 PILOT、StageRoute（含 MIP，复现论文报告数字或给出差距说明）。
- 补：最便宜/最强 fixed router、随机审计、固定比例审计（a∈{0.05,0.1,0.2}）、风险自适应审计。
- D3 改名为「固定比例审计参考基线」，不标本文方法；「D3 对 π 不敏感」属构造性质，不作发现。

## 4. T2 主张改写

- π* 交叉点放附录，报逐 seed 分布。判读规则：0.12 处 ΔJ 区间整体 <0 且 0.10 处整体 >0 才保留 (0.10,0.12)；否则写「条件区间 + 逐 seed 分布」。

## 5. T4 卖家风险排序 / 欺诈检测
- 任务：给定卖家前 k 轮公开行为，排序其后续欺诈概率；指标 AUROC、AP、precision@10。
- 特征白名单（锁定，Coding 已按代码核）：报价、声明模型、延迟分布、billed tokens、合规标签、历史成交量。listed_quality（挂牌公开值，固定不变）。共 7 项，最终版（协议于 2026-11-10 冻结）。
- 卖家自报 confidence 删除（Coding 核实：按实际服务模型输出计算、theft 截短后近乎标签、mock 下按对错分布抽样）；若要保留需模拟器另给与输出无关的自报字段。
- 已删除（Coding 核实泄漏）：答案长度（theft 按字符比例截短真实输出，长度随 tokens_actual 变）；任何质量分（`trust.quality` 用了审计揭示的真实模型，属泄漏；若加无参照质量分，必须不用标准答案、不用真实模型身份，且写明算法）。
- 黑名单（标签泄漏，发布前剥离）：tokens_actual 及 tokens_actual−tokens_billed、audits.hit/miss/label_correct/fraud_realized、slash_amount、delist_rounds、learned_q_*、actual_model、confidence、任何 attack 字段。
- 切分：按 run 切。seed 0–13 训练、14–19 测试（≥20 seed 时按 70/30 取整）；特征用前 32 轮，标签取后 16 轮欺诈与否；测试 run 不出现在训练中。
- 基线：逻辑回归、GBDT、规则（价格偏低 + billed tokens 异常）。
- 必报对照：「去掉延迟」（6 项特征）与完整 7 项并列，按攻击类型分列 AUROC/AP，报二者差值及 bootstrap 区间，用于说明成绩中有多少来自延迟（swap 换模型时延迟可能直接暴露身份）。

## 5b. 模拟器改造（v1.0 范围内，排在主表之后）
- 把隐藏推理 token 与可见答案分开记：theft 只截隐藏推理，可见答案按正常生成。改完后可见答案长度可回白名单（须再过泄漏检查）。理由：真实推理 token 市场里买家只看得到答案、看不到推理，这是 T4 的现实性所在。
- 主表（§1–§4）不依赖本项；先跑主表，再改模拟器重跑 T4。T4 报改造前（7 项特征，另附去掉延迟的 6 项对照）与改造后两版。

## 口径补正（2026-11-10，定于 40 卖家主表开跑前，非看结果后改；Review 裁定；不改判读规则）
1. Q 不做 token 加权：取策略卖家在场轮次的混合策略 q 的不加权均值，q_swap、q_theft（及 q_downgrade）分列，主列取各攻击模式的简单平均。（加权在未成交时无定义；Q 量的就是意图，暴露归 E。）
2. 必报「尾段有成交的 run 比例」。尾段无成交时攻击与否收益相同，q 不受反馈驱动、不可识别：该策略在帕累托图上画空心点，正文不对其 Q 作威慑解读。
3. Q 晋升门槛按每个 π 分别检验，须所有 π 都过；官方检验用 EXP3 或 fictitious play（hedge 结果可附录）。3 个策略时 τ≥0.6 即排序完全一致；40 卖家主表策略数更多时门槛才有区分度。
4. T2 中 reputation_rounds=0 无停牌，剔除规则在有停牌的设定下生效，正文注明。
5. 本批 hedge τ 检验不计入晋升判定；Q 是否升主列留到 40 卖家全套基线上，用 EXP3 或 fictitious play 按每个 π 判。
6. T4 指标按测试 run 单算：每个 run 内对该 run 的卖家排序，算 AUROC、AP、precision@10，再对测试 run 取平均；区间按 run 做 bootstrap。不跨 seed 合并排序。
7. E 主列按成交笔数（代码现状，保回归基准）；按 token 加权的 E_tok 作副列，主列不改。

## T4 补充（2026-11-10，Review 核定；PILOT 加跑前写入；不替换本轮官方设定）
