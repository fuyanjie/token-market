# Cross-Border D&B v1.1 实验协议（Review 有条件放行后的修订稿，确认冻结后再开 WP1）

日期：2026-11-10。依据：v1.1 修订规划（傅老师）、`docs/v1.1/SIM_NOTES.md`（commit e097950）、Review 冻结前三处修订。
本协议冻结后记 sha256；开跑后不改。要改就升版本号、全部重跑。所有格子都报，不挑选。

## 0. 统一统计口径
- 至少 20 seeds（0–19）；同一 seed 配对差；10,000 次 bootstrap，95% 百分位区间；配对 bootstrap 双侧 p 值。
- Holm 校正按「族」做，α=0.05。族的定义见各节。
- 「显著」= Holm 校正后 p<0.05。点估计与区间照常全报。
- Q 只在**可识别**格子上判：该格子「尾段有策略卖家成交的 run 比例」>50%。不可识别的格子 Q 照报、标记，不参与任何显著性判定，也不作威慑解读。
- 已知（SIM_NOTES 实测）：π 只影响 PILOT 与 StageRoute；其他路由的 π 行完全相同。因此只有 PILOT 与 StageRoute 跑 π∈{1, 0.1, 0}，其余路由只跑 π=1，有效样本按 20 seeds 计。

## 1. WP1 router × audit 析因

### 1.1 设计
- 路由：cascade、PILOT、StageRoute、strongest、cheapest。
- 审计率 a：{0, 0.01, 0.02, 0.03, 0.05, 0.10, 0.20}，外加 risk-adaptive。理由：SIM_NOTES §6 实测盈亏平衡，见下方写死的 a*(P)；v1.0 网格除 a=0 外全在平衡点上或以上；0.01–0.03 落在 P=0.25 时「攻击仍划算」一侧。
- 罚金 P：{0.25（默认）, 0.0625（P/4）, 0.015625（P/16）}。跑前写死的盈亏平衡点 a*(P)=S/(d·P)（区间来自 SIM_NOTES §6 的卖方价格范围，开跑后不得按结果改）：
  - P=0.25：a* ≈ 0.044–0.050
  - P=0.0625（P/4）：a* ≈ 0.18–0.20
  - P=0.015625（P/16）：a* ≈ 0.71–0.80
- **P/16 的用法：** 这一档上，本协议的整个 a 网格（含 0.20 与 risk-adaptive）都低于 a*，全部落在「攻击仍划算」一侧。它只用来看攻击划算时 E、Q 的表现，不能拿来证明审计有效，也不计入 §1.4 结果 1。
- π：PILOT 与 StageRoute 跑 {1, 0.1, 0}；cascade、strongest、cheapest 和「cascade + trust」只跑 π=1。
- 审计检查统一为 identity + length。这是相对 v1.0 的设定变化：v1.0 的 cascade 审计臂用 identity + length，但非 cascade 路径默认只有 identity，theft 抓不到。正文 T1 必须写明这一变化，**不能和 v1.0 的审计臂直接比数**。
- trust_feedback=false 用于全部路由，保证同一路由在各审计水平下的路由规则相同；另加一臂「cascade + trust」，用于对照 v1.0 的审计臂（对照时仍须注明检查与反馈设定若有不同）。
- 卖家学习规则：全网格用 egreedy（v1.0 默认），48 轮。这是诊断结果。决策点 A 所需的「收敛轮数 + 多学习规则」检验见 §1.3。
- 每格报：E、E_tok、Q 及 q_swap/q_theft/q_downgrade、准确率、每任务成本、尾段有策略卖家成交的 run 数，以及每 run 策略卖家尾段成交笔数。

### 1.2 效应与族
- 效应 = 同一路由、同一 P、同一 π、同一学习规则下，各审计水平相对 a=0 的配对差（E 与 Q 各一个）。
- 报告用的 Holm 族 = 同一路由、同一学习规则、同一 π 下的全部 (a, P) 对比，E 与 Q 合在一族。
- 决策点 A 的总判定另设一族：把 PILOT 与 strongest 在默认参数（P=0.25，π=1）下的全部审计对比（E 与 Q）并成一个 Holm 族，避免「两个路由各试一次」。P/16 不进这一族。
- 「审计降低 E/Q」= 配对差为负且显著。

### 1.3 决策点 A 的检验格子
- 在 WP2 给出的建议轮数下，对 strongest、PILOT（两者尾段成交 20/20，Q 可识别）重跑 §1.1 的审计 × P 网格，π=1，学习规则 egreedy、fictitious play、EXP3 三种。
- 「两种以上学习规则方向一致」= 至少 2 种学习规则下该效应显著且同号，并且没有任何一种学习规则显著反号。
- 已知风险：SIM_NOTES §1c 指出 EXP3 的奖励被 P 归一化后几乎平坦，可能学不动。若 EXP3 在 WP2 中不收敛，它的结果照报，但不计入「方向一致」，此时须由 egreedy 与 fictitious play 两种都满足。

### 1.4 决策点 A 的三种结果（判定在先，跑数在后）
1. **默认参数下审计有效**：在同一路由内，P=0.25、a∈{0.05, 0.10, 0.20, risk-adaptive} 中至少一个，按 §1.3 判定 E 或 Q 显著降低且方向一致；且该效应在 §1.2 的决策点 A Holm 族（PILOT 与 strongest 合并）校正后仍显著。两路由分别报告，不得在未合并校正的情况下用「任一路由过了」作为总判定。→ T1 改为 router × audit 表，标题保留 audit。
2. **只在部分罚金/审计率下有效**：结果 1 不成立，但在某些 (a, P) 格子上，于同一路由内按 §1.3 成立。→ 把盈亏平衡写成 benchmark 的可调维度，如实说明默认参数下审计无效。同时报告有效格子是否都满足 a ≥ a*(P)，a*(P) 用 §1.1 写死的区间。P/16 的格子即使显著，也只说明「攻击仍划算时」的表现，不能当作审计有效的证据。
3. **全部无效**：任何格子都不满足 §1.3。→ 标题与主张去掉 audit/deterrence，主线改为稀疏标签下的采购与策略性造假，T2 为主结果。
- cascade + a=0 对 cascade + a>0 的对比单独报告，用于区分路由与审计的贡献，不参与上述判定（cascade 的 Q 预计不可识别）。

## 2. WP2 轮数与收敛
- n_rounds ∈ {48, 200, 500}，**n_tasks = 10·n_rounds**，buyer 预算按 n_tasks/480 等比放大（SIM_NOTES §5：只改 n_rounds 会让实际轮数和尾窗出错，预算也会耗尽）。
- 已知：任务从 80 题池循环抽取，200/500 轮时每题重复约 25×/62×，有效多样性仍是 80 题，正文须写明。
- 路由：PILOT、strongest、cascade + a=0.1；π=1；20 seeds；学习规则 egreedy、fictitious play、EXP3。
- 收敛判据：同一 seed 的「第三个四分之一段 Q − 最后四分之一段 Q」，其 95% 区间**整体落在 [−0.05, 0.05] 内**。只要求区间包含 0 会让噪声大的格子更容易过关，所以加等价边界。
- 建议轮数 = 三种学习规则在 PILOT 与 strongest 上都满足收敛判据的最小 n_rounds。cascade 的 Q 若不可识别则不参与。500 轮仍不收敛就如实报告；某一学习规则不收敛，则按 §1.3 处理。

## 3. WP3 定价（δ 网格）
- δ ∈ {0, 0.10, 0.30, 0.50}，相对同一声称模型（1.5B）的诚实卖家报价打折。
- 卖家利润 = 收入 − 按实际服务模型计的成本 − 罚没（SIM_NOTES §1 显示 v1.0 已按此计，WP3 只确认不重复计）。
- Q-C 的验收按规划报 cheapest 的 E。须同时报出每个 δ 下最便宜的策略卖家在 cheapest 排序中的名次。
- 已知风险（SIM_NOTES 实测）：cheapest 最先买的是 12 个 mock 卖家（期望成本 0.0050–0.0076），δ=0.5 时策略卖家的期望成本约为 0.011–0.015，仍排在它们后面，因此 δ 网格大概率不会让 cheapest 的 E 离开 0。这不是失败，按规划如实报原因即可。是否改设定（例如让策略卖家声称更便宜的模型，或把 mock 卖家移出 cheapest 的候选）属于改设定，须由傅老师决定，不在本协议内自行加。
- 另须报：δ 较大时折后价低于诚实服务成本 0.12/1k，诚实服务本身就亏钱，攻击被价格「逼出来」。正文解读 Q 时要写明这一点。
